# docs/plan/

`SafeRoute_Plan_v7_MVP.pdf` is the committed copy of the design, product and technical
architecture plan (v7). Every prompt cites its sections as "Plan v7 §N". Claude Code reads the
relevant sections during `/start-prompt`.

[`addendum-v7.1.md`](addendum-v7.1.md) (since P009a) records implementation facts and product
decisions made after v7.

[`addendum-v7.2.md`](addendum-v7.2.md) (since P010c) records the launch geography (West Bengal,
with Kolkata as the first pilot area for community safety data), the three coverage layers and
the rule for public coverage claims.

[`addendum-v7.3.md`](addendum-v7.3.md) (since P010d) replaces "reports only in active regions":
reports are accepted anywhere inside West Bengal, and publication is gated region by region.

[`addendum-v7.4.md`](addendum-v7.4.md) (since P012d) records the post-MVP product direction: the
order of features after the MVP, the journey engine, and the guardrails for every future feature.

[`addendum-v7.5.md`](addendum-v7.5.md) (since P012g) supplements v7.4 with a long-term direction,
live local context, and a staged path to it. It builds nothing and changes no MVP scope.

[`addendum-v7.6.md`](addendum-v7.6.md) (since P012h) records a concept: credits for verified
place contributions, the decisions already taken about it, and the gates before any build. It
is Proposed, builds nothing and changes no MVP scope.

**Reading order: PDF → v7.1 → v7.2 → v7.3 → v7.4 → v7.5 → v7.6.** Where they differ, the later document wins. A full v8 will
be written after the MVP and company registration.

Do not edit the PDF. A new plan version is committed as a new file, and the change is noted in an ADR.
