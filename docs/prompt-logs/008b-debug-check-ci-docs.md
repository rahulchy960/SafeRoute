## 7. Decisions & ADRs

ADR 0009 gains **point 14: developer tools are debug-only** (source sets, empty release hooks,
layout test, APK scan, CI on contract changes and release builds). No new ADR.

- **`gradlew.bat`: committed.** The change is real, not line endings: `git diff
  --ignore-cr-at-eol` and `--ignore-all-space` still show it. It removes `set CLASSPATH=` and
  `-classpath "%CLASSPATH%"`, which do nothing because the script starts Java with `-jar`.
  Gradle 9.6.0's own template has no `CLASSPATH` either, but it differs in other places too
  (`setlocal EnableExtensions`, an `endlocal &` launch line); this is a partial update, not a
  regenerated wrapper. `.\gradlew.bat --version` works (Gradle 9.6.0). A full `gradle wrapper`
  regeneration, which would also replace `gradlew` and the wrapper jar, is a follow-up.
- **Variant source sets instead of a runtime flag.** `if (BuildConfig.DEBUG)` would hide the row
  but still ship the screen in the release APK. With `src/debug` and `src/release` the release
  build never compiles it.
- **The extension point is two functions in `navigation/`,** defined in both source sets, so
  `SafeRouteNavHost` stays the only place that knows routes, and Settings stays stateless with a
  `developerEntry` slot.
- **`ServerCheck` is in the `core.network` package** (in `src/debug`). The ViewModel gets
  `ProbeResult`s and never a Retrofit or generated type.
- **Nothing is sent when no server is configured.** The placeholder resolves nowhere; the screen
  says "No server configured" and how to fix it.
- **Failures are grouped for the screen:** no connection; unavailable (anything `isRetryable`,
  such as 503 `db_unavailable`); sign-in needed (401); server error (status and code); unexpected
  (status if any). The code shown is the server's machine code, never `detail`.
- **"Last request id"** is the readiness probe's id, or the health probe's when readiness has
  none (a connection failure has no server id).
- **The CI also proves that a release without the property fails.** On a developer machine the
  property is set, so CI is where that path is exercised on every run.

## 12. Learning notes

- **Build types and source sets.** A build type (debug, release) is a way to build the same app.
  Gradle compiles `src/main` into every build, plus the folder named after the build type:
  `src/debug` only into debug builds, `src/release` only into release builds. Code that exists
  in only one of them can't leak into the other.
  <https://developer.android.com/build/build-variants#sourcesets>
- **Same function, two folders.** `developerDestinations()` exists in `src/debug` (adds the
  screen) and in `src/release` (does nothing). Shared code calls it without knowing which build
  it is in. Both must have the same signature, or one of the builds stops compiling.
- **`src/testDebug`.** Tests for debug-only code. They run with `testDebugUnitTest`.
- **Slot.** `SettingsScreen` takes `developerEntry: @Composable () -> Unit`; the caller decides
  what goes there (a row in debug, nothing in release).
- **`viewModelScope`.** A coroutine scope owned by the ViewModel. When the screen leaves the
  back stack, its work is cancelled.
- **`Dispatchers.setMain` in tests.** Android's main thread doesn't exist in a JVM test; the test
  replaces the main dispatcher with one it controls.
- **Hilt test replacements.** `@UninstallModules` removes a module's bindings for one test and
  `@BindValue` provides a replacement, here a fake server check, so the test never touches a real
  server. <https://developer.android.com/training/dependency-injection/hilt-testing>
- **Health vs readiness.** `/health` answers "is the process up?" without touching the database;
  `/health/ready` answers "can it serve requests that need the database?". Two separate lines on
  the screen show which one is failing.
- **Release APK scan.** An APK is a zip file; the compiled code is in `classes*.dex` and the
  string table in `resources.arsc`. Searching them for the debug screen's class names proves it
  is not shipped.
- **Gradle wrapper.** `gradlew` / `gradlew.bat` download and start the right Gradle version, so
  nobody installs Gradle by hand. The scripts are generated by Gradle and normally only change
  when the wrapper is regenerated.
