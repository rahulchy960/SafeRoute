## 7. Decisions & ADRs

ADR 0027, note of 2026-10-13 (P014c2b).

- **A Room table for three values.** The name is personal data and may not go into the
  settings file (flags only, ADR 0012). One row, one store, erased in one step.
- **The name is whatever the user types**, optional, 30 characters, one line. No account
  name exists and none is asked for from the server.
- **Erased with the contacts**, not only at sign-out: a name for alerts has no purpose once
  alerts are stopped.
- **The alert language is a choice of its own**: the app's, English or Bengali.
- **The sound is off by default** (ADR 0027, decision 10) and says why. One built-in tone
  on the alarm volume; no sound file, no permission, no override of silent mode.
- **The runner reads the setting once per countdown**, and a setting that cannot be read
  means no sound: the countdown never depends on it.
- **Notice version 4**: the rule in CLAUDE.md is that a change in what an SOS sends or
  stores changes the notice in the same prompt. A name is both.
- **None of the three counts in "N things to fix".**

## 8. Security & privacy notes

- **New personal data on the phone: the name the user types for alerts.** It is in the
  app's private database, is never sent to SafeRoute's server, is never logged, and is
  hidden when the types that hold it are printed. It leaves the phone only in the SMS to
  the user's own contacts. It is erased when alerts are stopped, at sign-out and when the
  account is blocked. Not backed up.
- The local database is still not encrypted (an open point of ADR 0027 since P014a1); the
  name is one more reason to decide that before the closed test.
- **No new permission.**
- What is typed into the field stays in memory until "Save".
- The notice text is a draft for a lawyer; the Bengali for a native speaker.

## 9. Known issues & risks

- **Unverified on a phone.** Whether the tone is audible, how loud it is, and what silent
  mode and Do Not Disturb do to it is known for no phone.
- **A sound can give a person away.** It is off by default, and the screen says so.
- **Every tester must agree to the notice again**: the fourth version in five days.
- **A user can type any name**, also someone else's. The alert still comes from their own
  phone number.
- **A text field inside a dialog hung the tests** (section 3). The cause is not known; the
  screen does not use one. A follow-up, because other screens may want such a dialog.
- A name set on one phone is not on the user's other phone: it is not synced, on purpose.
- 21 Bengali strings are new or changed drafts and **need human review before release**.
- About 965 added lines in `android/` (about 490 of app code, strings and the schema's
  entry, about 475 of tests), above the ~800 of the prompt after the cut; the table, its

## 12. Learning notes

- **Room migration.** When a table is added, the database version goes up and a
  `Migration` lists the SQL that brings an installed app's database to the new layout.
  Room compares the result with the exported schema file, which is committed.
  [Docs](https://developer.android.com/training/data-storage/room/migrating-db-versions)
- **A one-row table.** A fixed primary key (always 1) and "upsert" make a table behave
  like one record of settings.
- **DataStore or Room.** Small flags go into DataStore; personal data goes into the
  database, where it is handled with the rest of what belongs to the account.
- **ToneGenerator and audio streams.** Android has separate volumes ("streams") for media,
  ringtone and alarms. A tone on the alarm stream follows the alarm slider.
  [Docs](https://developer.android.com/reference/android/media/ToneGenerator)
- **`remember` and `rememberSaveable`.** `remember` keeps a value while the screen is on;
  `rememberSaveable` also writes it to the saved state. A typed name uses the first.
- **Radio buttons and switches for TalkBack.** The whole row is the button
  (`selectable`, `toggleable` with a role), so the label and the state are read together.
