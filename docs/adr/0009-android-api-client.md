# ADR 0009: Android API client (generated at build time) and network rules

- **Status:** Accepted
- **Date:** 2026-10-03
- **Prompt:** P008 (split: P008a generation, network stack and tests; P008b debug check screen, CI, README and diagram)
- **Plan refs:** Plan v7 §5.1, §6.1–§6.3, §12.2, §12.4

## Context

- The contract is `contracts/openapi.json` (OpenAPI 3.1, generated by the backend, [ADR 0004](0004-api-contract-and-conventions.md)). Plan v7 §6.2 says the Kotlin client is generated from it and that request and response models are never written by hand.
- The repository is public. The staging address must not be in it, and Claude Code must not see it.
- Every `/v1` call carries a Firebase ID token ([ADR 0006](0006-authentication-and-roles.md)): 401 means refresh and retry once, 503 means retry with backoff, 403 is final. Sign-in itself arrives with P009.
- The app will later talk to other servers too (map tiles, geocoding, routing). A token that reaches one of them would let it act as the user.
- SafeRoute handles phone numbers and locations. Anything written to a log can end up in a bug report.
- The R0 spike of P008 showed that OpenAPI Generator 7.25.0 reads the 3.1 contract and that its output compiles with Kotlin 2.4.20 and AGP 9.4.1 (details in the [P008a log](../prompt-logs/008a-android-api-client.md)).

## Decision

1. **The client is generated on every build and is never committed or edited.** The Gradle task `generateApiClient` (OpenAPI Generator, plugin `org.openapi.generator`, version pinned in the catalog) reads `contracts/openapi.json` and writes Retrofit interfaces and `@Serializable` models to `android/app/build/generated/openapi`, in the package `com.saferoute.app.core.network.generated`. It is a generated source folder of every variant, so compilation always uses the current contract and a breaking contract change fails the Android build.
2. **Generator settings:** `kotlin`, library `jvm-retrofit2`, `kotlinx_serialization`, coroutines, `Response<T>` return types. Of the generator's supporting files only the UUID and date-time serializers and `CollectionFormats` are kept. Its `ApiClient` is not used: the app builds its own client (points 4 to 8).
3. **Only `core/network` knows OkHttp and Retrofit.** The rest of the app calls `apiCall { api.operation() }` and gets an `ApiResult` (`Success` or `Failure` with an `ApiFailure`). The generated code is an implementation detail of `core/network`.
4. **`IdTokenProvider` is the only link to sign-in.** `suspend fun idToken(forceRefresh: Boolean): String?`. Until P009 the bound implementation always returns null. The network layer never stores a token.
5. **Tokens go to the API and nowhere else.** `AuthInterceptor` adds `Authorization` only when the request has the same scheme, host and port as the API base URL. The authenticator applies the same test.
6. **401:** the authenticator asks for a refreshed token once and retries once. It gives up when there was no token, the retry also fails, or the refresh returns nothing or the same token.
7. **Automatic retries are for idempotent requests only.** `GET` and `HEAD` are retried on 503 and on a connection failure, at most twice, after 300 ms and 900 ms plus jitter; `Retry-After` is honoured up to 5 s. `POST`, `PUT`, `PATCH` and `DELETE` are never retried by this layer. Timeouts: connect 10 s, read 30 s, write 30 s, whole call 45 s.
8. **No body is ever logged.** Release builds log nothing. Debug builds log one line per attempt: method, path without query string, status, duration and request id. No header, no host, no exception message.
9. **Errors:** `application/problem+json` is decoded with the generated `ProblemDetails`. `code` stays a string and unknown codes are passed on. A body that is not a complete problem document becomes `Unexpected(status)`; its text is discarded. `apiCall` throws nothing but `CancellationException`.
10. **JSON is strict but tolerant of additions:** unknown keys are ignored; values are not coerced; lenient parsing is off.
11. **HTTPS only.** The network security config refuses cleartext traffic for every host and trusts only the system certificate authorities, in debug builds too. `INTERNET` is the only permission added.
12. **The base URL comes from the Gradle property `saferoute.apiBaseUrl`**, kept in each developer's user-level `gradle.properties` or passed by CI with `-P`. The repository default is `https://api.invalid/`, which resolves nowhere. The build fails on a value that is not `https://…/`. **A release build fails when the property is missing.** The URL is never logged or shown; the app may only say whether one is configured.
13. **No certificate pinning for now.**

## Alternatives considered

- **Commit the generated client, with a CI drift check.** Reviewable in pull requests and no generator in the build. Rejected: generated code in the repository invites hand edits, doubles every contract diff and can drift between the check and a release.
- **Write the models by hand.** Rejected by Plan v7 §6.2; it is how a client and a server drift apart unnoticed.
- **Down-level the contract to OpenAPI 3.0 inside the build, or use another generator.** Kept as the fallback had the spike failed. Not needed.
- **The generator's own `ApiClient`.** Rejected: it needs two more libraries, can log bodies, and uses a lenient `Json`.
- **Base URL in a tracked file or in `local.properties`.** A tracked file publishes the address. `local.properties` belongs to Android Studio (it rewrites it) and is per checkout; a user-level Gradle property is outside every checkout and can't be committed by accident.
- **Match the token rule on the host only.** Rejected: a different port or `http` on the same host is a different server.
- **Retry writes automatically.** Rejected until each write carries an `Idempotency-Key` (P013 to P015): a repeated `POST` could create two SOS sessions.
- **Certificate pinning now.** Rejected for now: staging runs on Cloud Run ([ADR 0007](0007-gcp-staging-topology.md)), whose Google-managed certificates rotate, and a wrong pin makes the app unable to reach the API until an update is installed. To be decided with the production domain.

## Consequences

- A contract change shows up in the Android build at once. The price: every build runs the generator when the contract changed (about half a minute the first time, then `UP-TO-DATE`), and the first build needs the Gradle Plugin Portal.
- OpenAPI Generator labels its 3.1 support "beta". A contract feature it mishandles would surface as a build failure or a wrong type; the round-trip tests in `GeneratedClientTest` decode the backend's real JSON shapes to catch that. Upgrading the generator is a deliberate change with those tests as the gate.
- An `enum` in the contract becomes a closed Kotlin enum. An unknown value on a response fails decoding (a handled `Unexpected`, not a crash). Response fields that may gain values should be open strings in the contract, as `role` and `locale` already are.
- Retrofit refuses a null `@Body`: an optional request body is sent as an empty object.
- A developer without the property gets a debug app that says "no server configured". CI release builds must pass the property (P022).
- OkHttp's built-in recovery from a failed connection attempt (`retryOnConnectionFailure`) stays on; it is separate from point 7 and is reviewed together with the idempotency policy for writes.
- Follow-ups: the Firebase `IdTokenProvider` (P009); the retry policy for writes (P013 to P015); the pinning decision; offline behaviour and caching; a generator upgrade policy.
- We would revisit point 1 if the generator stopped handling the contract or made builds unreasonably slow.
